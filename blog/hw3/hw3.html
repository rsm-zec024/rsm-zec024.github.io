This assignment expores two methods for estimating the MNL model: (1) via Maximum Likelihood, and (2) via a Bayesian approach using a Metropolis-Hastings MCMC algorithm.

1. Likelihood for the Multi-nomial Logit (MNL) Model

Suppose we have \(i=1,\ldots,n\) consumers who each select exactly one product \(j\) from a set of \(J\) products. The outcome variable is the identity of the product chosen \(y_i \in \{1, \ldots, J\}\) or equivalently a vector of \(J-1\) zeros and \(1\) one, where the \(1\) indicates the selected product. For example, if the third product was chosen out of 3 products, then either \(y=3\) or \(y=(0,0,1)\) depending on how we want to represent it. Suppose also that we have a vector of data on each product \(x_j\) (eg, brand, price, etc.).

We model the consumer’s decision as the selection of the product that provides the most utility, and we’ll specify the utility function as a linear function of the product characteristics:

\[ U_{ij} = x_j'\beta + \epsilon_{ij} \]

where \(\epsilon_{ij}\) is an i.i.d. extreme value error term.

The choice of the i.i.d. extreme value error term leads to a closed-form expression for the probability that consumer \(i\) chooses product \(j\):

\[ \mathbb{P}_i(j) = \frac{e^{x_j'\beta}}{\sum_{k=1}^Je^{x_k'\beta}} \]

For example, if there are 3 products, the probability that consumer \(i\) chooses product 3 is:

\[ \mathbb{P}_i(3) = \frac{e^{x_3'\beta}}{e^{x_1'\beta} + e^{x_2'\beta} + e^{x_3'\beta}} \]

A clever way to write the individual likelihood function for consumer \(i\) is the product of the \(J\) probabilities, each raised to the power of an indicator variable (\(\delta_{ij}\)) that indicates the chosen product:

\[ L_i(\beta) = \prod_{j=1}^J \mathbb{P}_i(j)^{\delta_{ij}} = \mathbb{P}_i(1)^{\delta_{i1}} \times \ldots \times \mathbb{P}_i(J)^{\delta_{iJ}}\]

Notice that if the consumer selected product \(j=3\), then \(\delta_{i3}=1\) while \(\delta_{i1}=\delta_{i2}=0\) and the likelihood is:

\[ L_i(\beta) = \mathbb{P}_i(1)^0 \times \mathbb{P}_i(2)^0 \times \mathbb{P}_i(3)^1 = \mathbb{P}_i(3) = \frac{e^{x_3'\beta}}{\sum_{k=1}^3e^{x_k'\beta}} \]

The joint likelihood (across all consumers) is the product of the \(n\) individual likelihoods:

\[ L_n(\beta) = \prod_{i=1}^n L_i(\beta) = \prod_{i=1}^n \prod_{j=1}^J \mathbb{P}_i(j)^{\delta_{ij}} \]

And the joint log-likelihood function is:

\[ \ell_n(\beta) = \sum_{i=1}^n \sum_{j=1}^J \delta_{ij} \log(\mathbb{P}_i(j)) \]

2. Simulate Conjoint Data

We will simulate data from a conjoint experiment about video content streaming services. We elect to simulate 100 respondents, each completing 10 choice tasks, where they choose from three alternatives per task. For simplicity, there is not a “no choice” option; each simulated respondent must select one of the 3 alternatives.

Each alternative is a hypothetical streaming offer consistent of three attributes: (1) brand is either Netflix, Amazon Prime, or Hulu; (2) ads can either be part of the experience, or it can be ad-free, and (3) price per month ranges from $4 to $32 in increments of $4.

The part-worths (ie, preference weights or beta parameters) for the attribute levels will be 1.0 for Netflix, 0.5 for Amazon Prime (with 0 for Hulu as the reference brand); -0.8 for included adverstisements (0 for ad-free); and -0.1*price so that utility to consumer \(i\) for hypothethical streaming service \(j\) is

\[ u_{ij} = (1 \times Netflix_j) + (0.5 \times Prime_j) + (-0.8*Ads_j) - 0.1\times Price_j + \varepsilon_{ij} \]

where the variables are binary indicators and \(\varepsilon\) is Type 1 Extreme Value (ie, Gumble) distributed.

The following code provides the simulation of the conjoint data.

import numpy as np
import pandas as pd

# set seed for reproducibility
np.random.seed(123)

# define attributes
brand = ["N", "P", "H"]   # Netflix, Prime, Hulu
ad = ["Yes", "No"]
price = np.arange(8, 33, 4)  # 8, 12, ..., 32

# generate all possible profiles
import itertools
profiles = list(itertools.product(brand, ad, price))
profiles_df = pd.DataFrame(profiles, columns=["brand", "ad", "price"])
m = profiles_df.shape[0]

# assign part-worth utilities (true parameters)
b_util = {"N": 1.0, "P": 0.5, "H": 0}
a_util = {"Yes": -0.8, "No": 0.0}
def p_util(p):
    return -0.1 * p

# number of respondents, choice tasks, and alternatives per task
n_peeps = 100
n_tasks = 10
n_alts = 3

# function to simulate one respondent’s data
def sim_one(id):
    datlist = []
    for t in range(1, n_tasks + 1):
        # randomly sample 3 alts (without replacement)
        sampled = profiles_df.sample(n=n_alts, replace=False).copy()
        sampled["resp"] = id
        sampled["task"] = t
        # compute deterministic portion of utility
        sampled["v"] = sampled["brand"].map(b_util) + sampled["ad"].map(a_util) + p_util(sampled["price"])
        # add Gumbel noise (Type I extreme value)
        e = -np.log(-np.log(np.random.rand(n_alts)))
        sampled["e"] = np.round(e, 10)
        sampled["u"] = sampled["v"] + sampled["e"]
        # identify chosen alternative
        sampled["choice"] = (sampled["u"] == sampled["u"].max()).astype(int)
        datlist.append(sampled)
    return pd.concat(datlist, ignore_index=True)

# simulate data for all respondents
conjoint_data = pd.concat([sim_one(i) for i in range(1, n_peeps + 1)], ignore_index=True)

# remove values unobservable to the researcher
conjoint_data = conjoint_data[["resp", "task", "brand", "ad", "price", "choice"]]

3. Preparing the Data for Estimation

The “hard part” of the MNL likelihood function is organizing the data, as we need to keep track of 3 dimensions (consumer \(i\), covariate \(k\), and product \(j\)) instead of the typical 2 dimensions for cross-sectional regression models (consumer \(i\) and covariate \(k\)). The fact that each task for each respondent has the same number of alternatives (3) helps. In addition, we need to convert the categorical variables for brand and ads into binary variables.

import pandas as pd

# Step 0: Load the conjoint data
df = pd.read_csv('conjoint_data.csv')

# Step 1: One-hot encode brand and ads variables
df['Netflix'] = (df['brand'] == 'N').astype(int)
df['Prime'] = (df['brand'] == 'P').astype(int)
df['Ads'] = (df['ad'] == 'Yes').astype(int)
# Note: Hulu is the reference category; price is already numeric

# Step 2: Create group_id for each (respondent, task) pair
df['group_id'] = df['resp'].astype(str) + '-' + df['task'].astype(str)

# Step 3: Sanity check: each group must contain exactly 3 options and exactly 1 choice
assert df.groupby('group_id').size().eq(3).all()
assert df.groupby('group_id')['choice'].sum().eq(1).all()

# Step 4: Sort by group for reshaping
df = df.sort_values(['group_id'])

# Step 5: Reshape into 3D arrays for MNL model
X = df[['Netflix', 'Prime', 'Ads', 'price']].values
y = df['choice'].values
n_group = df['group_id'].nunique()
n_alt = 3
n_feat = X.shape[1]
X_reshaped = X.reshape((n_group, n_alt, n_feat))
y_reshaped = y.reshape((n_group, n_alt))

4. Estimation via Maximum Likelihood

import numpy as np
from scipy.optimize import minimize

# Multinomial logit log-likelihood
def mnl_loglike(beta):
    util = np.dot(X_reshaped, beta)   # shape [n_group, n_alt]
    exp_util = np.exp(util)
    prob = exp_util / exp_util.sum(axis=1, keepdims=True)
    ll = (y_reshaped * np.log(prob)).sum()
    return -ll  # 因为要用minimize，所以取负号

# 初始参数
init_beta = np.zeros(n_feat)

# 最大似然估计
res = minimize(mnl_loglike, init_beta, method='BFGS')
mle_beta = res.x

# 输出MLE结果
print('MLE estimates:', mle_beta)

# 计算标准误和95%置信区间
se = np.sqrt(np.diag(res.hess_inv))
ci_lower = mle_beta - 1.96 * se
ci_upper = mle_beta + 1.96 * se

# 输出表格
print('\nParameter      Estimate     StdErr     95% CI')
for i, name in enumerate(['Netflix', 'Prime', 'Ads', 'Price']):
    print(f'{name:<10} {mle_beta[i]:>8.3f}   {se[i]:>8.3f}   ({ci_lower[i]:.3f}, {ci_upper[i]:.3f})')

5. Estimation via Bayesian Methods

5.1 Priors and Posterior

import numpy as np

# Prior: N(0, 5) for the first three coefficients, N(0, 1) for price
def log_prior(beta):
    return -0.5 * ( (beta[:3]**2/25).sum() + (beta[3]**2/1) )

# Posterior: log-likelihood + log-prior
def log_posterior(beta):
    return -mnl_loglike(beta) + log_prior(beta)

5.2 Metropolis-Hastings MCMC Sampler

np.random.seed(42)
n_iter = 11000    
burnin = 1000     
beta_init = np.zeros(X_reshaped.shape[2])
chain = [beta_init]
accepted = 0

# Proposal: add Gaussian noise to each parameter
def propose(beta):
    step = np.zeros_like(beta)
    step[:3] = np.random.normal(0, 0.05, 3)
    step[3] = np.random.normal(0, 0.005)
    return beta + step

for i in range(n_iter):
    current = chain[-1]
    candidate = propose(current)
    log_acc = log_posterior(candidate) - log_posterior(current)
    if np.log(np.random.rand()) < log_acc:
        chain.append(candidate)
        accepted += 1
    else:
        chain.append(current)
chain = np.array(chain[1:])      # remove the initial state
accept_rate = accepted / n_iter
print('Acceptance rate:', accept_rate)

# Discard burn-in
chain_burned = chain[burnin:]
Acceptance rate: 0.567

The acceptance rate was around 56.7%, which is within a good range. This suggests that the sampler was working properly and exploring the posterior efficiently

6. Discussion

If we were working with real (not simulated) data, the parameter estimates would just reflect what people actually prefer, based on their real choices. The numbers might not match our simulated values exactly, but we could still interpret the meaning based on their signs and sizes.

When we see that \(\beta_\text{Netflix} > \beta_\text{Prime}\), it means people generally like Netflix more than Prime, assuming everything else (ads, price) is the same. In other words, Netflix gives a higher “utility” or satisfaction to respondents than Prime does, compared to Hulu (which is our base category).

As for the price parameter being negative, that totally makes sense. A negative \(\beta_\text{price}\) means that the higher the monthly price, the less likely someone is to choose that streaming option. This matches what we’d expect in real life—most people prefer cheaper options, all else being equal.

If we wanted to build a more realistic model for real-world conjoint data, we’d probably use a multi-level or hierarchical model. The main idea is that, instead of assuming everyone has the exact same preferences (the same betas), we let each person have their own set of betas, which are drawn from an overall population distribution. So, for example, maybe some people care more about ads, while others are more sensitive to price.

To simulate data for this kind of model, we’d randomly draw individual preference parameters for each respondent from a normal distribution (or something similar) instead of just using the same values for everyone. And when estimating the model, we’d use techniques like hierarchical Bayes or mixed logit to figure out both the overall average preferences and how much individuals differ from that average. This way, the model better captures real-life differences in what people want.
